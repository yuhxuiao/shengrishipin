## 三、两条已验证的路线(2026-09-27 Demo)

### 路线甲:扁平精致化(纯代码)
路线甲 Demo(30s,带原片音轨;视频已清理)。五层视差 + 摄像机 + 接触阴影 + 光圈转场 + 弹入字幕。成本零、确定性满分,但天花板是"精致的扁平卡通",到不了用户心头好(banana 毛绒 3D 风)。

### 路线乙:AI 融合(主推)⭐
路线乙 Demo(8s,带原片音轨;视频已清理)。**gpt-image-2 绿幕精灵(JS 键控零抠边痕迹)+ AI 金色时刻背景板 + 同一套引擎动效**。首次生成即达到 banana 参考图质感,帧级控制、角色一致性(同一张精灵图走全片)、零视频 API 依赖。
- 关键突破:v4 失败的"抠图痕迹"被**纯色绿幕提示词 + 绿色度键控 + 去溢色**解决(`demo2.js keyGreen`,40 行,引擎内完成);精灵与黄昏底色的色温差用 `ctx.filter='saturate(1.07) sepia(0.10)'` 调和。
- 挖臂动作镜头的解法:对同一精灵用 gpt-image-2 `/images/edits` 生成 2-3 个挖臂姿态变体(举臂/半举/落地),引擎做姿态切换 + makeWarp 区域变形过渡。
- 配角五辆车 + 小狗同样各生一张绿幕精灵,错峰弹性入场(roleMotion 参数已备好)。

### 路线乙+:AI 融合 + 关节绑定(最终推荐)⭐⭐
路线乙+ Demo(8s,带原片音轨;视频已清理)。在路线乙基础上解决"精灵是死的"问题:
- **T-pose 资产**:生图时要求"手臂高举与身体分离",绿幕键控后按多边形切成 身体/大臂/小臂+铲斗 三件套(关节圆钮归大臂防割裂)
- **正运动学引擎** `web/src/rig.js`:大臂绕肩、小臂绕肘,角度沿骨骼链传递;角色级 squash/位移/旋转与关节角复合
- **零裁切痕迹(已攻克)**:① 外轮廓完全交给绿幕 alpha,多边形只圈"属权"且全走绿区;② 关节处大小臂用**同圆心同半径的圆弧切口**(旋转不变性),切口永远重合;③ 肘关节盖独立成件最后绘制,盖住切口;④ 身体 erase 掩码外扩 14px 防碎屑残留;⑤ `demo3.html#parts` 调试视图可平铺检查每件的切分结果
- 效果:毛绒皮克斯质感的开开可以**挥手、挖土、弹跳、眨眼**(眨眼用面罩色眼睑覆盖即可),动作全是代码关键帧——与剧情/语音的帧级对齐能力100%保留
- 同类外部方案调研:Meta Animated Drawings 只支持类人生物、ToonCrafter 需本地 GPU 推理、Rive/Spine 需要 GUI 手工绑定——本方案等价于"用代码做 Spine",最适合本项目

### v7 全片落地清单(路线乙+)
1. 资产(半天~1天,~15 张图):开开 T-pose(已验证)+ 四车一狗 T-pose 精灵(吊车臂/搅拌筒/推土铲同法拆件)+ 白天/黄昏/夜晚背景板 3-5 张 + 蛋糕/礼物道具;固定风格咒语 + 剧组色盘(smy 方法论)。

# 附:初版方案(保留备查,多数已被路线乙覆盖)

## 一、调研结论(一句话)

2026 年精美 2D 儿童动画的行业共识 = **AI 出美术资产 + 确定性动画引擎做导演控制**。
纯 AI 视频(Seedance/Kling/Veo/grok-imagine)锁不住 20+ 镜头的主角一致性;纯代码画若不讲究运动设计就是"会动的 PPT"。
我们项目已有确定性 Canvas 引擎(web/src/),角色一致性天然满分,缺的是**镜头语言与动画语言**——这正是那批仓库里最可搬运的部分。

### C. 备用赛道(AI 美术增强,不改变管线)
- **AI 背景板**:用 grok-imagine-image 生成绘本风背景(近景草地/黄昏派对/星空夜三张),引擎里作为 f=0.4~1 层位图叠加,代码角色压在上层——画面丰富度再上一档,角色一致性不受影响。制作方案里 grok2api Super 账号验证后可做。
- **AI 视频只用于"无主角大远景"**(如片头航拍感空镜),不进正片叙事镜头。
- 提示词纪律(smy/梵高版可照搬):固定风格咒语逐字复用 + 剧组色盘声明 + 咆哮体硬约束 + "感受世界"情绪门禁(期待/惊喜/狂欢/温馨四类,各自预定义色比/运镜节奏)。
